# CLAUDE.md

Guidance for AI assistants working in this repository.

## Project

HA Knob: Home Assistant controller firmware for the LilyGo T-Encoder Pro (ESP32-S3R8,
16 MB flash, 8 MB OPI PSRAM, 390x390 round AMOLED, touch, rotary encoder, buzzer).
PlatformIO + Arduino framework. Current version 0.5.0 (Step 5: Home Assistant connection).

The approved specification and change log live outside the repo in
`~/.claude/workspace/chgreq/LilyGo T-encoderPro - HA Controller/chg001/`.
Implement one specification step at a time.

## Commands

```
pio run -e t-encoder-pro                 # build
pio run -e t-encoder-pro -t upload       # flash (COM14)
pio run -e t-encoder-pro -t uploadfs     # flash LittleFS web assets (data/)
pio run -e t-encoder-pro -t erase        # wipe flash incl. NVS config + secrets + ap_pw; upload again after
pio device monitor                       # serial monitor
pio test -e native                       # host unit tests (needs MSYS2 ucrt64 gcc on PATH)
%USERPROFILE%\.platformio\penv\Scripts\python.exe tools/serial_check.py --port COM14 --expect "<regex>" --timeout 20
```

`serial_check.py` never resets or flashes; it waits for each `--expect` regex and exits 0/1.
USB-CDC drops output printed before the host enumerates, so assert on the repeating `HB`
line, not only on `BOOT`.

## Layout and rules

- `include/board_pins.h`: the only place GPIO numbers are defined.
- `include/version.h`: `FW_VERSION`; bump it with releases.
- `include/lv_conf.h`: LVGL 9.2.2 template with project changes listed at the top.
- `lib/core/`: **pure C++17**. No Arduino, ESP-IDF or FreeRTOS includes; only the STL and
  ArduinoJson. Everything here must be testable with `pio test -e native`.
  Hardware glue lives in `src/`.
- `test/native/test_*/`: Unity host tests. `test/embedded/` is reserved for on-device tests.
- `src/main.cpp` is wiring only: it polls the HAL modules, logs, and forwards to `ui::`.
- `src/hal/*`: one namespace per device (`hal::display`, `hal::touch`, `hal::encoder`,
  `hal::button`, `hal::buzzer`); single hardware instance each, state is file-local.
- `src/ui/*`: `ui::` screen manager plus `ui/screens/*`. All LVGL calls happen on the main
  loop only. Use the project fonts `ui_font_20/28/56` (declared once, in `include/lv_conf.h`
  via `LV_FONT_CUSTOM_DECLARE`, so `lvgl.h` is enough), never `lv_font_montserrat_*`
  (disabled; ASCII only). Fonts are generated by `tools/gen_fonts.sh`; never hand-edit them.
- `lib/core/src/config/ConfigModel`: config schema, `fromJson` (always returns a valid
  config: stored or defaults + `LoadStatus`), `toJson`, `toRedactedJson`, `validate`,
  `mergePatch` (returns merged config + `SecretChanges` Keep/Set/Clear), `migrate`.
  JSON-building APIs take an optional `ArduinoJson::Allocator*`; on the device pass
  `PsramAllocator::instance()` (`src/hal/PsramAllocator.h`).
- `lib/core/src/control/DomainActions` is the single source of truth for per-domain
  encoder actions, presses and step ranges. Do not duplicate that table elsewhere (the web
  UI gets it from `/api/meta/actions` in Step 6).
- `src/config/ConfigStore`: the only code that touches NVS namespace `haknob`. All public
  methods lock its mutex; never call LVGL or the HA socket while holding it.
- `src/net/WifiManager` (`net::wifi`): STA / setup AP / captive DNS / mDNS state machine,
  main loop only. `src/net/WebServer` (`net::web`): ESPAsyncWebServer routes.
- `lib/core/src/ha/`: `HaUrl` (the only URL parser; ConfigModel's `parseUrlEndpoint` is an
  alias of it), `HaProtocol` (message builders + classifier), `HaSession` (connection
  state machine, clock-injected, talks to a `Transport` interface; native tests use a fake
  transport). `src/ha/HaClient` (`ha::`) is only the transport adapter (links2004
  `WebSocketsClient`) plus logging; main loop only, like all HA socket I/O. Never enable
  `coalesce_messages`. The token lives only in `ConfigStore` and the session; log
  `token_set len=N`, never the value.
- **Web callbacks run in the `async_tcp` task**: never call LVGL, `WiFi.*` or main-loop state
  from them. They read the snapshot published by `net::web::publishNetwork` (mutex), write
  config **only via `ConfigStore::applyPatch()`** (never `save()`, which bypasses the token
  and Wi-Fi guards), and request work (config re-read, scan, reboot, factory reset) with
  atomic flags the main loop takes (`net::web::take*`).
- `lib/core/src/web/RequestGuard`: Host allow-list, captive-portal redirect, method,
  CSRF (`application/json` + `X-HAKnob: 1`), body limit (16 KB), Basic auth check. Every
  request passes it in the server middleware. Never add CORS headers.
- Web UI (`data/`): vanilla JS, no build step, DOM text via `textContent` only (no
  `innerHTML`), no inline scripts or styles (the CSP forbids them). Clients always send
  whole config sections (section replace is literal), `ssid` in every `wifi` section, `url`
  in every `ha` section, and the Wi-Fi password together with the SSID (`null` = open).
- `lib/core/src/input/QuadratureDecoder.h` is header-only and `always_inline` because the
  encoder ISR calls it; keep anything it uses free of out-of-line calls and flash tables.
- All library versions are pinned exactly in `platformio.ini`; record any change and its
  reason in README "Library versions".

## Hardware facts and gotchas

- **IO3 (VCI_EN) must be HIGH** before the display is initialised.
- Display: Arduino_GFX `Arduino_ESP32QSPI` + `Arduino_CO5300(bus, 4, 0, false, 390, 390, 0,0,0,0)`,
  `begin(40000000)`. LVGL flush areas must be rounded to even x1/y1 and even width/height
  (done in an `LV_EVENT_INVALIDATE_AREA` handler).
- **IO0 is the encoder push button and the BOOT strapping pin**: holding the knob during
  reset enters download mode. Never use a hold-at-boot gesture for features.
- **Never call `Serial.setDebugOutput(true)`, and never define `CONFIG_ASYNC_TCP_DEBUG` or
  `ASYNCWEBSERVER_LOG_DEBUG`**: they route library/ESP-IDF output into the USB serial
  without the `logPrintf` protection below (and blocking writes from the `async_tcp` task).
- **Serial: always log with `util::logPrintf()` (`src/util/Log.h`), never `Serial.print*`.**
  Core 2.0.17's `HWCDC::write()` busy-loops when the USB host is attached but the port is
  not being read and the TX buffer is full; it counts retries down from the TX timeout, so
  `setTxTimeoutMs(0)` wraps around (~49 days). `setup()` uses `setTxTimeoutMs(1)` (0 also
  made `Serial.flush()` discard the buffer).
  That froze the main loop after a replug (stale Wi-Fi snapshot -> `Host: <ip>` got 403,
  Wi-Fi scans never finished) until a monitor was opened. `logPrintf` only writes a line
  that fits into the free buffer (4 KB, set in `setup()` before `Serial.begin`) and counts
  the rest (`LOG dropped=N`). It is header-only and not ISR-safe.
- **The screen is the knob cap**: pressing it also clicks the button (touch ~120 ms before
  `BTN down`). User decision: all press actions come from the button; touch gives swipes
  only (`core::SwipeClassifier`); taps must never trigger an action.
- **Encoder ISR is IRAM-safe**: registered with `gpio_install_isr_service(ESP_INTR_FLAG_IRAM)`
  + `gpio_isr_handler_add`, pins read with inline `gpio_ll_get_level`. Arduino's
  `attachInterrupt`/`digitalRead` are in flash on core 2.0.17 (`CONFIG_ARDUINO_ISR_IRAM` is
  off). **Do not call `attachInterrupt` elsewhere**: Arduino would reuse this IRAM-flagged
  ISR service and its flash-resident dispatcher could then run with the cache disabled.
  Check placement after changes: `xtensa-esp32s3-elf-nm -C firmware.elf | grep encoder`
  (ISR and `readAb` must be at 0x4037xxxx/0x4038xxxx, data at 0x3fcxxxxx).
- Buzzer uses the core-2.x LEDC API (`ledcSetup` + `ledcAttachPin`), not core-3 `ledcAttach`.
- SensorLib drivers are given `sda/scl = -1` because `Wire.begin(5, 6)` is called first
  (otherwise core 2 logs "bus already initialized").

## Step 1 hardware results (2026-10-14)

- **Detected touch variant: CST816** (I2C 0x15), so the unit is the newer
  `TFD12MASBCTB4_V0_07` panel with the CO5300 controller.
- `BOOT`/`HB`: `psram=8386215 flash=16777216 touch=CST816`, free heap about 282 KB at boot.
- **Transitions per detent: 2, clockwise = positive. Confirmed by the user on hardware**
  (exactly ±1 per click, no missed steps). Rest positions are AB = 00 and 11; the sequence
  00 -> 10 -> 11 -> 01 -> 00 is clockwise.

## Step 2 (2026-10-14)

- `QuadratureDecoder` counts detents on arrival at a rest state (00/11) that differs from the
  previous rest state, with the direction of the final transition; invalid jumps count
  nothing and a jump onto a rest state re-syncs the phase. (Replaces the Step 1 resetting
  accumulator.) The Step 1 `ENCRAW` ring buffer is gone; the encoder exposes only an atomic
  detent counter read as a delta by the main loop.
- Fonts: `ui_font_20/28/56` cover ASCII, Latin-1, Latin Extended-A and the bullet;
  20/28 also the `LV_SYMBOL_*` glyphs. Flash cost about 336 KB in total (56 px alone 208 KB).
  The status screen shows "Køkken Æble Ørn" as a font check.
- Swipe: >= 80 px horizontal, <= 700 ms, |dx| >= 2|dy| (`SwipeClassifier::Config`).
- Pending user confirmation: Danish string legible, `BTN long`/`verylong`, swipes.

## Step 3 (2026-10-14)

- NVS namespace `haknob`: `cfg` (blob, JSON, <= 8 KB), `wifi_pw`, `ha_token`, `web_pw`,
  `ap_pw` (10 chars, generated on first boot, survives `factoryReset()`).
- First boot (nothing stored) logs `CFG defaults reason=missing` and saves the defaults, so
  later boots log `CFG loaded controls=N`. Corrupt / invalid / newer-schema data gives
  defaults for that boot but is not overwritten until the next save.
- `BOOT ... cfg=<defaults|loaded>` and `HB ... ctl=<N> cfg=<defaults|loaded>` expose the load
  state (`cfg` = how this boot got its config).
  `device.brightness` is applied at boot.
- Duplicate `entity_id`s across controls are allowed (Q2). Domains are limited to light,
  climate, cover, fan, media_player, switch, input_boolean (Q5).
- Secrets in a patch: absent or `""` = keep, string = set, `null` = clear. Token guard: a
  `ha.url` change to a different host:port, or an https -> http downgrade, needs a new token
  in the same patch (`token_required`); clearing the URL clears the token; a path-only
  change or an http -> https upgrade on the same host:port keeps it.
- Wi-Fi guard (mirrors the token guard, against rogue APs): a `wifi.ssid` change (byte for
  byte) to a non-empty value needs `wifi.password` in the same patch, as a string or `null`
  (open network), else `wifi.password`/`password_required`. An empty SSID after the patch
  always clears `wifi_pw`; likewise an empty `ha.url` always clears `ha_token` (a secret is
  never stored without the setting it belongs to).
- `ConfigStore::applyPatch` sets `MergeResult::cfgWritten` when the cfg blob was written,
  even if a later secret write failed (`ok=false`, `nvs_write_failed`).
- `ConfigStore::save` order: remove the old `ha_token`/`wifi_pw` if they change (abort on
  failure), write `cfg`, write the new secrets. Worst case after a failure is "new cfg,
  secret missing". The in-memory config mirrors NVS once `cfg` is written.
- `ap_pw` is generated with `bootloader_random_enable()` around `esp_random()` (RF is not up
  at that point). A stored `cfg` that is empty, > 8 KB or unreadable is `Corrupt` (never
  overwritten automatically).
- **Custom `partitions.csv`, NVS 64 KB** (was 20 KB in `default_16MB.csv`) so the 8 KB cfg
  blob can be rewritten safely. otadata 0xE000, app0 0x10000 / app1 0x640000 (0x630000
  each), spiffs 0xC70000 (0x370000), **nvs 0xFE0000**, coredump 0xFF0000; 0x9000-0xE000
  unused. Changing the table requires `pio run -e t-encoder-pro -t erase` + upload.
- **PlatformIO offset pitfall:** upload addresses do NOT come from the partition table.
  The Arduino builder always writes `boot_app0.bin` to 0xE000 and PlatformIO writes the app
  to `upload.offset_address` (default 0x10000). otadata must stay at 0xE000 and app0 at
  0x10000, otherwise the board boot-loops (`rst:0x3 RTC_SW_SYS_RST`; happened in Step 3
  with app0 at 0x20000). NVS is found by label, so it may live anywhere. Check after any
  table change: `pio run -e t-encoder-pro -t envdump` (FLASH_EXTRA_IMAGES,
  ESP32_APP_OFFSET) against `gen_esp32part.py .pio/build/t-encoder-pro/partitions.bin`.
- Size: 24 controls with 48-byte labels and typical entity ids serialise to about 3.8-4 KB;
  extreme cases (255-char entity ids) are rejected by `validate()` as `controls/too_large`.
- `parseUrlEndpoint()` in ConfigModel is a minimal URL check; Step 5's `HaUrl` should take it
  over so URL parsing has one implementation.

## Step 4 (2026-10-15)

- Libraries: `ESP32Async/AsyncTCP@3.5.0`, `ESP32Async/ESPAsyncWebServer@3.12.1` (as
  planned, no deviation). The "Ignored `Hash` dependency" warning is ESP8266-only.
- `WiFi.persistent(false)` and `WiFi.setAutoReconnect(false)`: credentials exist only in
  `haknob`; retries are scheduled by WifiManager (15 s before the AP fallback, 60 s with
  the AP up). The setup-only state runs `WIFI_AP_STA` with an idle STA so scans work
  without a mode change.
- Wi-Fi restarts only when the SSID or password in use actually differ
  (`net::wifi::applyConfig` compares them), 1 s after the HTTP response. `mergePatch` no
  longer reports `restartWifi` for an SSID that was and stays `""`.
- After `applyPatch` with `cfgWritten` (also on `nvs_write_failed`) the handler sets
  `configDirty`; the main loop re-reads the config (brightness, Wi-Fi, hostname/mDNS).
- `HB` gained `wifi=<off|ap|sta|ap_sta> ip=<ip>`.
- Round 2 (2026-10-15):
  - STA link state is read from ESP-IDF every 100 ms (`esp_wifi_sta_get_ap_info` + STA
    netif address), not `WiFi.status()`. Retries never disconnect an association that is
    still waiting for DHCP, or a running scan.
  - Scans use `esp_wifi_scan_start` directly (active, 120 ms max dwell, own 15 s timeout,
    start retried for 6 s while the driver is busy). `WiFi.scanNetworks(true)` +
    `scanComplete()` report a scan as failed after `max_ms_per_chan * 20` (6 s) while the
    driver is still scanning, and the next start then fails too.
  - `ConfigStore` skips unchanged writes: cfg blob compared byte for byte with the stored
    one, a secret Set to its stored value or a Clear of an absent key becomes Keep.
    `MergeResult::secretsWritten` joins `cfgWritten`; the web handler re-reads the config
    if either is set.
  - The static handler only serves files listed from the LittleFS root at boot, so misses
    (`/api/x`, `/favicon.ico`) never reach LittleFS and its `vfs_api` error logging.
- AP SSID uses the last two bytes of the STA MAC (this unit: `HA-Knob-043C`).
- App size 1.52 MB (was about 0.94 MB): Wi-Fi stack, web server, mDNS, LittleFS.
- Upload timing: about 53 s with nothing to rebuild (30 s PlatformIO pre-upload checks,
  16 s write at about 925 kbit/s with compression and the stub). Not a config problem;
  slow uploads come from a full rebuild after any `platformio.ini` change (3-4 min).

## Step 5 (2026-10-15)

- **links2004/WebSockets 2.7.3, not 2.7.2**: 2.7.2 calls `WiFiClient::setTimeout(5000)`,
  which core 2.x takes as seconds (5000 s socket/stream timeouts: a stalled peer could block
  the main loop for over an hour). 2.7.3 converts it for core < 3.
- **`WEBSOCKETS_MAX_DATA_SIZE` cannot be overridden in 2.7.x**: `WebSockets.h` defines it
  (15 KB) without `#ifndef`, so `-D` only produces "redefined" warnings and the library
  keeps 15 KB; a larger frame closes the connection (1009). The flag is not set. Step 6
  (`get_states`, up to MBs) needs another way (open question).
- `HaSession` states: `no_config`, `connecting`, `authenticating`, `subscribing`, `ready`,
  `auth_failed`, `backoff`. Backoff 1, 2, 4, 8, 16, 30 s (consecutive failures; reset at
  Ready, new URL/token, Retry). `auth_failed` never reconnects by itself (not even after a
  Wi-Fi change); only a new URL/token or `POST /api/ha/retry` leave it. Retry also ends a
  backoff wait. `HaSession::send()` fails the connection only once even when the transport
  reports the close from inside `sendText()`. Timeouts: 20 s open -> auth_required, 10 s auth answer, ping every 30 s
  after auth_ok, 10 s pong, 15 s pending requests. Ids restart at 1 per connection.
- Step 5 passes no entity ids (no subscription; Ready right after auth_ok). The session
  already implements Subscribing for a non-empty list; Step 6 wires the controls' ids and
  live resubscription.
- `lastError` explains why the session is not Ready (`connect_failed`, `connection_lost`,
  `dns_failed`, `connect_timeout`, `auth_timeout`, `pong_timeout`, `send_failed`,
  `network_down`/`network_lost`, `auth_invalid: <HA message>`, `invalid_url`); cleared on
  Ready. `ha_version` is cleared by every new attempt.
- `ha.url` validation and the token guard accept exactly what v0.4.0 accepted. `HaUrl`
  flags a `?`/`#` (`hasQueryOrFragment`); the session refuses such a URL (`no_config`,
  `invalid_url`). **https URLs are refused by the session** (`no_config`,
  `tls_not_supported`, `Transport::open` never called; the adapter also refuses a TLS
  endpoint): TLS is out of scope (Q3) and the token must never go to a TLS port in
  plaintext. `validate()` still accepts https so no stored config becomes invalid.
- Transport: the host is resolved first with lwIP `dns_gethostbyname` run in the tcpip task
  (`tcpip_callback`), so an unresolvable name never blocks the main loop; the library's own
  blocking lookup then hits lwIP's DNS cache. The TCP connect itself is synchronous: a host
  that does not answer blocks the main loop up to 2 s per attempt
  (`-DWEBSOCKETS_TCP_TIMEOUT=2000`, `#ifndef`-guarded in the library, unlike
  `WEBSOCKETS_MAX_DATA_SIZE`; also the handshake and read-progress timeout).
  The library's reconnect is disabled (interval 0 for the first `loop()` after `begin()`,
  then `ULONG_MAX`), its heartbeat is off, no `Origin`/`Sec-WebSocket-Protocol` header.
  `close()` from inside a library event is deferred until `loop()` returns.
- `HB` gained `ha=<state> heap=<bytes>`. Free heap: 167 KB at boot (Step 4: ~169 KB),
  ~165 KB while connected. App 1.69 MB (26.0 %).
- Web: HA tab (URL, write-only token, state, Retry, Remove). `/index.html%00` and other
  decoded NULs in a path are 404 (paths are compared with their full length). HEAD is 404
  everywhere (only GET reaches the handlers). Basic auth is checked before a POST body is
  buffered. WifiManager waits for a stopped scan's late `SCAN_DONE` (and frees it) before
  the next scan; mDNS is retried every 30 s while `MDNS.begin()` fails.

## Upcoming requirements

- Home Assistant is reached over plain `http`/`ws` on the LAN; TLS is not planned.

## Secrets

- Never commit Wi-Fi passwords, Home Assistant tokens or any credential; they live only in
  NVS on the device. Never log a token (log `token_set len=N` instead).
- Secrets are never part of `core::config::Config`; they flow only through
  `SecretChanges` and the `ConfigStore` getters, and appear in API output only as `*_set`.
- `.gitignore` excludes `.pio/`, `*.local.ini`, `secrets*`, `.env*`.
- Do not copy files from the LilyGo vendor repository (GPL-3.0); use hardware facts only.
